// 04

Conclusiones
y retos

El proyecto demostró que es posible construir un sistema RAG funcional sobre materiales académicos reales, integrando múltiples servicios en una arquitectura cohesiva.

✅ Logro

Pipeline completo funcionando de extremo a extremo: desde Canvas hasta respuestas generadas por Gemini.

⚠️ Limitación

El proceso de parseo y embedding es lento para grandes volúmenes de archivos, representando un área de mejora.

🔧 Reto

Integrar todos los módulos en un sistema unificado fue el mayor desafío, cada componente funcionaba de manera aislada antes de conectarlos.

🚀 Mejora futura

Incorporar CDC con Debezium y Kafka para sincronización automática, eliminando la necesidad del botón de Recargar manual.

Stack
técnico

Elegido para escalar desde un prototipo académico hasta un sistema real de búsqueda semántica sobre materiales universitarios.

Vector DB
Qdrant
Una colección por cada grupo, evitando materiales solapados de diferentes maestros
Embeddings
hf gemma4 embedings api
768 dimensiones, retrieval_query, open source y local first
LLM
gemma4:26b / gemma4 legacy
Generación de respuestas fundamentadas atraves de gemma4 y el daemon de ollama
Data Lake
Azure Blob Storage
datalake para almacenar la bibliografia pre y post procesado
Base de datos
Neon PostgreSQL 17
Usuarios, cursos, sync logs, documents metadata y relaciones estudiante-curso
Auth
Neon Auth + JWT
httpx, re-auth automático en 401
Parser
docling
PDF, DOCX, PPTX → Markdown OCR + Transformers text extraction
Dedup
canvas downloader
Open source rust-based api wrapper to scrap and fetch course and documents' critical data
